## 6. Endpoints

### POST `/api/leads/:id/requirements` — initiation
Request: `{ "provider": "PERPLEXITY" | "GEMINI" }`
Flow: provider 400 → lead 404 → `leadPainContextAssembler.assemble(leadId)` (exact Research version via 036 FK + canonical qualifications.id; context errors → 404) → **persisted Pain resolution**: `latestPainAnalysisVersion(leadId)` (latest `pain_analyses.analysis_version` — canonical completed Pain state per project convention; none → 404 `REQUIREMENTS_PAIN_ANALYSIS_NOT_FOUND`) → `painVersionManager.getVersion(leadId, v)` returns the persisted analysis with **persisted pains (real UUIDs)** → `extractRequirements(leadId, {companyName, industry, website, summary, evidence, versionId: researchVersionId (boundary mapping for the service's `researchData.versionId` contract), qualificationSummary, qualificationVersionId}, {id: painAnalysis.id, pains}, provider, {researchVersionId, qualificationVersionId, painAnalysisId})` → createTask stamps all three identity columns.
Response 201: `{ data: { taskId, prompt, researchVersionId, qualificationVersionId, painAnalysisId, status: 'READY' } }`

### POST `/api/leads/:id/requirements/result` — result submission
Request: `{ "taskId", "result" }`
Flow: 400 if missing → `getTask(taskId)` → ownership (task.leadId === path leadId, 404) → type 409 → identity read **from task row** (researchVersionId/qualificationVersionId/painAnalysisId; any missing → 409 `REQUIREMENTS_TASK_VERSION_IDENTITY_MISSING`) → persisted Pain loaded from DB (`db.pain_analyses.findUnique(painAnalysisId)` + lead check 404 → `painVersionManager.getVersion(leadId, analysis_version)`) → `processAnalysisResult(leadId, result, {versionId: researchVersionId, qualificationVersionId, evidence: []}, {id: painAnalysis.id, pains: painAnalysis.pains}, taskId)` → atomic transaction (guards + persistence + REVIEWED).
Response 201: `{ data: { taskId, requirementsAnalysisId (real UUID), analysisVersion, status, overallCompleteness, overallConfidence, requirementCount, painAnalysisId } }`
**Note:** evidence passed as `[]` at result time (research evidence lives in the Research context; the validator downgrades unevidenced requirements to UNKNOWN rather than failing). SourcePain membership validated against persisted pains. A future enhancement could pass the research evidence array from the initiation context if persisted.

### Error mapping
`REQUIREMENTS_TASK_ALREADY_REVIEWED→409`, `REQUIREMENTS_TASK_NOT_FOUND→404`, `REQUIREMENTS_TASK_TYPE_MISMATCH→409`, `REQUIREMENTS_TASK_LEAD_MISMATCH→409`, `REQUIREMENTS_PAIN_ANALYSIS_NOT_FOUND→404`, `REQUIREMENTS_TASK_VERSION_IDENTITY_MISSING→409`, `REQUIREMENTS_RESEARCH_VERSION_NOT_FOUND→404`, `REQUIREMENTS_QUALIFICATION_VERSION_NOT_FOUND→404`, `RESEARCH/QUALIFICATION_CONTEXT_NOT_FOUND→404`, `INVALID_PROVIDER/INVALID_REQUEST→400`, unknown→500.
